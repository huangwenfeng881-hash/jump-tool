## 一、一句话现状

**Vertrise 跃升是一个面向篮球/田径爱好者的「弹跳能力测量 + AI 动作诊断 + 训练计划」工具，形态是静态网站（Netlify）+ 套壳 Android App（原生分析 + WebView 承载网页工具），版本号 1.5.0（versionCode 9），技术上已经跑通「视频 → MediaPipe 姿态 → 弹跳指标 → AI 报告」的完整链路，但因为云端后端（Supabase）已被删除，账号/同步/付费全部处于关闭或空转状态，产品目前是「单机版可用、云端版残缺、商业化未闭环」的阶段，尚未上架。**

## 三、改进项

### P0（不修就用不了）

#### P0-1 账号与存储改为「本地优先」，云端降级为可选同步

- **问题**：问题 1、2、13、15。云端一挂，登录、保存、记录、榜单全废；而这套产品的核心价值（测一次、存一次、看进步）恰好全靠它。
- **具体做法**：
  1. 新增 `js/store.js`（IndexedDB 优先，localStorage 兜底），提供 `save(kind, row)` / `list(kind)` / `remove(kind, id)` / `exportAll()` / `importAll(json)`；记录统一带 `{id, kind, createdAt, source:'local'|'cloud', synced:boolean}`。
  2. 改造 6 个页面改用本地：`jump.html`（保存不再拦登录，先写本地）、`barbell.html`、`history.html`、`progress.html`、`checkin.html`、`profile.html` 的资料区。
  3. `js/auth.js` 保留云端方法，但所有读取改成「本地优先、云端补同步」；`login.html` 增加「不登录，直接用本地模式」入口，未登录时导航徽章显示「本地」。
  4. 云端恢复后加同步：登录时把 `source:'local' && !synced` 的记录批量 push，成功后标记 `synced`。
- **工作量**：2.5~3 人天（`store.js` 0.5 天 + 6 个页面改造 1.5 天 + 同步逻辑 0.5~1 天）。
- **风险**：浏览器清站点数据会丢（必须提供「导出 JSON 备份」并在保存成功 toast 里提一句）；历史云端数据无法迁移，需要用户自行备份；IndexedDB 在 WebView 内可用但需验证（`WebPageFragment` 已开 `domStorageEnabled`、`databaseEnabled`）。

#### P0-2 App 内网页工具改为包内资源（WebViewAssetLoader）

- **问题**：问题 5。App 的「弹跳测量 / 动作分析 / 杠铃测速 / 训练计划 / AI 教练」实际是加载 `https://jumptool.netlify.app/*`。境外静态站在国内移动网络下经常不可用，等于 5 个功能随时整页白给；也与「离线可用」的宣传矛盾。
- **具体做法**：
  1. Gradle 增加同步任务：把根目录 `*.html`、`css/`、`js/`、`mediapipe/`、`img/` 拷进 `android/app/src/main/assets/site/`（`Sync` 任务 + `preBuild` 依赖，避免手工复制双份维护）。
  2. `SitePages.kt` 增加 `ASSET_BASE = "https://appassets.androidplatform.net/assets/site/"`，`url(page)` 对站内页返回该地址；保留 `BASE` 用于「用浏览器打开官网」。
  3. `WebPageFragment.setupWebView()` 里挂 `WebViewAssetLoader`（`androidx.webkit:webkit` 已在依赖中，`build.gradle.kts:55`），`webViewClient.shouldInterceptRequest` 走 AssetLoader；`handleUrl()`（`:150-160`）的站内判断加上 `appassets.androidplatform.net`。
  4. 注意 `mediapipe/` 里 `vision_bundle.mjs` 是 ES module + wasm，必须 https 域才能跑：`appassets.androidplatform.net` 满足条件，`js/pose.js:19` 的 `MEDIAPIPE_BASE` 相对路径可直接命中包内资源。
- **工作量**：1.5~2 人天（含体积评估与 5 个页面的离线回归）。
- **风险**：APK 体积显著增大（`mediapipe/` + `pose_landmarker_lite.task` 估 +20~25MB，当前 34MB）；两套资源要同步，否则站点更新后 App 里还是旧版（建议同步任务里写入 `asset_version.json`，App 启动读版本号用于排查）；`file://` 的旧兜底逻辑要一并清理。

#### P0-3 密钥与签名口令止血

- **问题**：问题 6、7、8、9、10。任何人打开网页源码或反编译 APK 就能拿到智谱 Key 刷额度，签名口令也已随 git 泄露。
- **具体做法**：
  1. **你操作**：登录智谱开放平台 → 吊销 `d56cac79…` 这把 Key，重新生成。
  2. 新增服务端代理（Cloudflare Worker 或新 Supabase Edge Function，仓库已有 `supabase/functions/` 目录可直接复用）：前端/App 只调 `/api/ai-report`，Key 只存在 Worker 环境变量里；加简单的按设备或 IP 限流（例如 20 次/天）。
  3. `AiReportGenerator.kt:17-19` 改成请求代理地址，删除 `GLM_KEY` 常量。
  4. 删除 `js/supabase-config.js:134-141` 的 `GLM_API_KEY_ENC`、`GLM_CRYPTO_PASSPHRASE`、`GLM_API_KEY` 三个字段，`js/glm-crypto.js` 一并下架。
  5. `android/app/build.gradle.kts:27-34` 改为从 `local.properties` / 环境变量读取：`storePassword = findProperty("VT_STORE_PASS")`，`local.properties` 已在 `.gitignore` 之外 → 需补一行忽略规则。
  6. 是否清理 git 历史（`git filter-repo`）属于可选项：Key 已吊销后历史泄露不再是主要风险，但签名口令建议更换。
- **工作量**：代码 3~4 小时；Worker 部署 0.5 小时；git 历史清理可选 1 小时。
- **风险**：多一跳网络 → 报告生成延迟 +200~600ms（可接受）；代理若不做鉴权会被白嫖，必须加限流；换签名口令后已签名 APK 不能复用，但尚未上架所以无影响。

#### P0-4 定价与配额口径统一（短期关掉，中期做实）

- **问题**：问题 11、12。页面在卖会员，但产品实际是无限免费；支付后端又挂着 → 用户付费后什么都拿不到，属于最严重的信任伤害。
- **具体做法（短期，本版必做）**：
  1. `index.html:255-285` 定价区、「最受欢迎」「立即购买」等 CTA 换成「内测期全部免费」；`membership.html` 的购买按钮置灰并加说明；导航「会员」入口在 `CloudFeatures` 关闭时隐藏。
  2. 全站清理「免费每日 2 次 AI 分析」这类无法兑现的文案（`index.html:163,259,267,364` 等）。
- **具体做法（中期，后端恢复后）**：
  3. `ai-jump.html` 生成报告前调 `JTAuth.consumeAI('analyze')`，失败跳会员页；`js/auth.js` 的 `consumeAI` 已有完整实现，只差接线。
  4. 支付换到可用后端，并把 `functions/api/pay-callback.js:5` 的目标地址一起改掉。
- **工作量**：短期 2~3 小时；中期 1.5 人天（含支付联调）。
- **风险**：真开配额会立刻掉留存，免费额度要留够（建议每日 5 次）；个人开发者用聚合支付（EZFP）收单有合规风险，需确认是否要走官方渠道。

### P1（明显影响体验或留存）

#### P1-1 分析提速：顺序解码 + 缩放 + 模型单例

- **问题**：问题 16、17、18。这是 App 的核心功能，现在慢到用户会以为「卡死」。
- **具体做法**（`analyzer/PoseAnalyzer.kt`）：
  1. 用 `MediaExtractor + MediaCodec` 顺序解码，替换逐帧 `getFrameAtTime`；按 `sampleEvery` 抽帧后缩放到最长边 480px（与网页版对齐），再构造 `BitmapImageBuilder`。
  2. `PoseLandmarker` 提为 object 内单例 + 懒加载，只在进程结束/显式释放时 `close()`。
  3. `ui/AnalyzeFragment.kt:88-92` 默认抽帧档从「每帧」改成「每 2 帧」，并在选视频后先给「预计 30~60 秒」的预估（按时长×fps/档位估算）。
  4. 中断时保留已完成帧数，允许「继续分析」而不是从 0 开始。
- **工作量**：2~3 人天（解码管线重写最费时，含旋转/VFR/裁剪）。
- **风险**：部分老机型（尤其 MTK）MediaCodec 输出格式不统一，需 `COLOR_FormatYUV420Flexible` 兜底与回退到旧实现；降分辨率可能影响小人物场景的识别率，必须用 `test video/` 里 30 段带人工标注的样本做回归（`JumpAnalyzerRegressionTest` 可扩展）。

#### P1-2 本机历史记录 + 数据页重做

- **问题**：问题 13、14。数据 Tab 现在只有 3 个数字，用户看不到任何历史。
- **具体做法**：
  1. `LocalStore.kt` 增加明细存储（推荐 `SQLiteOpenHelper` 或 ` Room`；若不想加依赖，用 JSON 文件 + 原子写）。字段：时间、高度、腾空、起跳方式、五个指标、来源（原生/网页）、视频文件名。
  2. `ui/DataFragment.kt` 换成 `RecyclerView` 列表 + 点击进单条详情（可复用 `item_metric_card.xml`）。
  3. 加「导出 JSON / 导出 CSV」（`ACTION_CREATE_DOCUMENT`）与「清空记录」（二次确认）。
- **工作量**：1~1.5 人天。
- **风险**：只存指标不存视频，别让用户误以为视频被保存；`Room` 会加依赖与体积（约 300KB），如介意可用 JSON 方案。

#### P1-3 AI 报告本地兜底

- **问题**：问题 20。断网时 App 只能给一句「网络异常」，而宣传语写着「全部功能离线可用」。
- **具体做法**：`AiReportGenerator` 增加 `buildLocalReport(metrics)`——用已有 `buildMetricsText` 的数据 + 规则阈值输出「逐项评分 / 类型判断 / 1-3 条短板 / 训练建议」，模板风格可参考 `js/trainer-engine.js`；网络失败或超时自动降级，并在报告头标注「离线版报告」。
- **工作量**：0.5~1 人天。
- **风险**：本地报告质量弱于 LLM，文案要打磨，且不要让用户以为这就是 AI 输出（需明确标注）。

#### P1-4 修掉「提交反馈」死入口

- **问题**：问题 4。用户认真写完反馈，永远收到「提交失败」。
- **具体做法**：`CloudFeatures.ENABLED == false` 时，在 `AnalyzeFragment.onViewCreated` 里隐藏 `fragment_analyze.xml` 中反馈区所在容器（或用 `WebLinkBinder` 同样的隐藏策略）；同时提供「复制诊断信息」（指标 JSON + 机型 + 版本）到剪贴板，引导用户走邮件/反馈群。后端恢复后再开。
- **工作量**：1~2 小时。
- **风险**：少一条数据回流渠道；建议同期把诊断信息存本地日志，日后能一起上传。

#### P1-5 Web 端 CDN 依赖本地化

- **问题**：问题 2 的伴生问题。16 处页面从 jsdelivr 拉 supabase-js，`index.html:38` 拉 gsap，`ai-jump.html:11` 等拉 chart.js；CDN 不通时页面会直接抛 `window.supabase is undefined`，而 `js/auth.js:150` 会误报成「Supabase 未配置」，把网络问题伪装成配置问题。
- **具体做法**：下载 `@supabase/supabase-js`、`chart.js 3.9.1`、`gsap 3.12.5`、`lenis` 到 `js/vendor/`，16 处 `<script src>` 改本地；保留 CDN 作为兜底（学 `js/pose.js:99-114` 的双路逻辑）；`js/auth.js:150` 的错误文案改成「账号服务未就绪（可能是网络或未配置）」，并附排查提示。
- **工作量**：2~3 小时。
- **风险**：静态资源体积略增（chart.js 约 200KB）；版本要锁死，避免下次又漂。

#### P1-6 版本与文档一致性

- **问题**：问题 25、26、27。
- **具体做法**：根目录新增 `version.json`（`{versionName, versionCode, apkSize, apkUrl}`），`build.gradle.kts` 从它读版本号、`index.html` 下载区从它渲染；更新 `上架指南.md` 与 `android/README.md` 的版本号；把 `download/*.apk` 移出 git（改用 GitHub Release / 对象存储），`.gitignore` 增加 `download/`。
- **工作量**：2 小时（不含 APK 托管）。
- **风险**：下载链接要换到外部稳定地址（Netlify 或对象存储），需要你确认可用的托管位置。
